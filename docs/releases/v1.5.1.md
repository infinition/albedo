# Albedo 1.5.1

macOS Quick Look thumbnails. Windows and Linux builds are unchanged.

## macOS

- Fixed: the Quick Look extension was never launched. Its types conformed to `public.3d-content`, which Apple's own SceneKit extension claims, and system extensions take precedence. Albedo's types now conform to `public.data` only.
- Fixed: WebKit's content and GPU processes refused to start inside the extension sandbox. The extension now carries `com.apple.security.network.client`, which WebKit requires even though every request goes through the local `albedo://` scheme.
- Fixed: the page reported "Missing thumbnail job" because the scheme handler answered without an HTTP status. It now returns HTTP 200.
- Fixed: the rendered thumbnail filled only the bottom-left quarter. The drawing context is sized in pixels with an identity transform; the image is now drawn over the whole context.
- The release workflow renders a 3MF through `QLThumbnailGenerator`, the path Finder uses, instead of `qlmanage -t`, which never reaches modern extensions.

## Known limit

macOS declares its own types for `glb`, `gltf`, `fbx`, `obj`, `stl`, `ply`, `dae` and `usd*` and routes them to SceneKit regardless of any third-party extension. Finder therefore shows Apple's rendering for USDZ, OBJ, STL and DAE, and a generic icon for GLB, glTF and FBX. Albedo renders the formats it owns: 3MF, 3DS, VOX, AMF, PCD, XYZ, NIF, KF, KFA, WRL and VRML. See `docs/PLATFORMS.md`.

Verified on macOS 26 (Apple Silicon) with the extension built by `platform/macos/build.py`: 512x512 thumbnail of a 3MF through Quick Look, and GLB, glTF and OBJ through the application CLI. Builds remain ad-hoc signed and are not Apple-notarized.
